* Implementation Plan

Ordered by least work / most impact.
Each module should expose cascade-traceable NixOS/HM options: system sets defaults, host overrides, user promotes/demotes as permitted.

*Known risks:*
- Ph4 (LUKS-in-VM + SecureBoot emulation) is non-trivial — effort is Days, not Hours
- Ph9 workspace scope must not diverge from ~settings.*~ pattern — see note in that phase
- Ph10 (yad + Nix AST) is significant scope; treat as a separate project if pursued

** Phase 1 — Structural skeleton
:PROPERTIES:
:IMPACT: Unlocks everything; all later phases plug into this
:EFFORT: Hours
:END:

+ [ ] Port ~example/flake.nix~ host-auto-discovery pattern (~builtins.readDir ./hosts~) into repo root
+ [ ] Define a ~settings~ attrset with explicit scope as the first key in the hierarchy, passed as ~specialArgs~:
  #+BEGIN_SRC nix
  settings = {
    system.kernel.variant  = "zen";
    user.editor            = "neovim";
    workspace.devtools     = [ "nodejs" ];
    session.theme          = "nord";
  };
  #+END_SRC
  + Scope is structurally encoded — no field, no alias, no naming convention
  + Promote/demote = move option between ~settings.system.*~ / ~settings.user.*~ / ~settings.workspace.*~ / ~settings.session.*~
  + NixOS modules receive ~settings.system~; HM modules receive ~settings.user~; passed transparently via ~specialArgs~
+ [ ] Add ~hosts/TEMPLATE/~ with annotated stubs:
  + [ ] ~configuration.nix~ (system scope)
  + [ ] ~home.nix~ (user scope)
  + [ ] ~hardware-configuration.nix~
+ [ ] ~modules/system/users/~ — user definitions, groups, shells as cascade options (system scope; HM handles user scope)
+ [ ] ~modules/system/nix/~ — nix daemon: substituters, binary caches, experimental features, GC policy
+ [ ] ~lib/mkCascadeOption.nix~ — shared helper for defining options that are cascade-traceable; used by all module phases
+ [ ] ~lib/mkDE.nix~ — factory for DE enablement modules (used in Ph2 to avoid copy-paste drift)
+ [ ] ~nixcfg~ CLI — expose as flake app (~nix run .#nixcfg~), not a system package:
  + Interface contract (define before Ph1 ships; other phases depend on it):
    + ~nixcfg sync~ — rebuild and switch system + HM state
    + ~nixcfg update [INPUT]~ — update all or one flake input
    + ~nixcfg gc [Xd|full]~ — garbage collect by age or completely
    + ~nixcfg lock~ / ~nixcfg unlock~ — toggle dotfile write permissions
    + ~nixcfg promote <option> <from-scope> <to-scope>~ — move a ~settings.*~ entry between scopes
    + ~nixcfg build~ — build all host configs (CI / attic push)

** Phase 8 — App launcher configs
:PROPERTIES:
:IMPACT: Satisfies "App Launcher" requirement; enables system-wide custom launch configs
:EFFORT: ~1 day (small novel invention)
:END:

+ [ ] ~settings.system.launchConfigs~ — attrset keyed by app name
  + Each entry: ~{ runner, args, flags, condition }~
    + ~condition~: build-time Nix predicate ~pkgs: bool~ (e.g. detect install method, platform); evaluated at eval time, not activation time
    + For activation-time guards use a ~runtimeCondition~ string field (shell expression evaluated in wrapper script)
  + Generates wrapper scripts via ~pkgs.writeShellScriptBin~
  + Handles: runner-prefix syntax, positional args, conditional sections, install-method awareness
+ [ ] ~settings.user.launchConfigs~ — mirrors system schema; promote/demote = move entry between scopes

** Phase 9 — Workspace & Session scopes
:PROPERTIES:
:IMPACT: Completes the 4-level cascade (system → user → workspace → session)
:EFFORT: Days (most novel)
:END:

+ [ ] *Workspace* scope — *single source of truth is ~settings.workspace.*~*; ~devShell~ is a derived output, not a competing definition:
  #+BEGIN_SRC nix
  settings.workspace.devtools = [ "nodejs" "python3" ];
  # flake generates: devShells.default = mkShell { packages = map (x: pkgs.${x}) settings.workspace.devtools; }
  #+END_SRC
  + ~direnv~ + ~.envrc~ activates the derived ~devShell~ automatically
  + No separate ~devenv.nix~ / ~flake.nix~ in project root — workspace settings live in the cascade only
+ [ ] *Session* scope
  + Ephemeral overrides via ~environment.sessionVariables~ or HM activation reading e.g. ~~/.config/session.json~
+ [ ] *Config symmetry* helper
  + Implemented as ~nixcfg promote~ subcommand (see Ph1 interface contract)
